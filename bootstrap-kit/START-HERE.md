## 总 · 这到底是什么

一句话：**它不是程序、没有服务、不押钩子，是「1 份治理 SOP + 1 个纯文本脚手架」**。
把规则与技能契约放进 CodeBuddy 官方自动加载路径，靠宿主读取目录生效——所以「落地」= 把 15 个文件放到对的位置 + 装 1 个用户级基座；「验收」= 跑机检看真实退出码。

| 项 | 实测结果 |
|---|---|
| 脚手架 `codebuddy-eco/` | 15 文件（含 `.codebuddy/` 隐藏目录）；包内快照**不含 `.git`** |
| 治理 SOP（目录外） | 须与 `codebuddy-eco/` **同级** |
| 分层 | 技能 4 / 项目级规则 2 / 用户级基座模板 1 / 治理层 2 / 台账映射 4 / 机检 1 / 说明 1 |
| MANIFEST | 4 技能 / 5 规则格 |
| `~/.codebuddy/rules/`（用户级目标） | 落地前实测 **不存在** → 第 4 步必做 |
| git 状态（本轮已变） | 审查侧**本体**已 `git init`（本地 / 0 remote / 1 提交）；**包内快照仍不含 `.git`** → 新沙箱拿到后仍需自己 `git init`。详见 01-D8 |
| 机检基线 | 三模式 PASS 8 / WARN 0 / FAIL 0，真实退出码 0 |

## 分 · 三步走（细节在各分册）

1. **落地**：见 `02-COLD-START.md` 六步。核心三件——同级摆放、装用户级基座、三通道补齐；
   不押钩子；官方无 `machine-bootstrap --verify` 能力，本生态不提供、不宣称通过。
2. **验收**：见 `03-ACCEPTANCE.md`。核心——L1 三模式机检真实退出码 0；
   L2 中文/技能触发/条件注入用三态实测；L3 对面结果审查侧仅认 UNKNOWN。
3. **理由**：见 `01-DECISIONS.md`。不懂「为什么」最容易重踩：又用顶层自建路径、
   又押钩子、又把触发词堆回 `description`。

## 总 · 收口

**一句话**：技能 4 个住 `.codebuddy/skills/`，规则按「用户级基座装 `~/.codebuddy/rules/` +
项目级常驻/条件两格留 `.codebuddy/rules/` + 台账留 `docs/`」三分离，SOP 必须同级；
落地靠「放对目录 + 同级 + 装基座」，验收靠机检真实退出码与对面三态实测。

数据自洽已在审查侧证过（本地三模式全绿、快照逐字节一致），但「另一会话加载后真跑通」
这一层不由本包宣布——**它在对面，是 UNDETERMINED，直到对面自己跑出三态报告为止**。
